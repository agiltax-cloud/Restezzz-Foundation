# Rest Ezzz — Live Site Content Migration & Integration Plan

## Goal
The restored live website is now a first-party content source.

The rebuild must **preserve and reuse valuable existing content**, but all reused content must be submitted to the new strategic direction and information architecture rather than copied blindly into the old structure.

## Core rule

```text
OLD / CURRENT LIVE CONTENT
          ↓
   CAPTURE VERBATIM
          ↓
     CLASSIFY
          ↓
 ┌────────┼─────────┬─────────┬─────────┐
 ▼        ▼         ▼         ▼         ▼
KEEP    ADAPT     MERGE     ARCHIVE    RETIRE
          ↓
      REMAP INTO
      NEW JJG / IA
          ↓
      FACT CHECK
          ↓
     CONTENT EDIT
          ↓
    FOUNDATION REVIEW
          ↓
       PUBLISH
```

## Classification states

### KEEP
Content remains accurate, useful and aligned with the new direction. Preserve wording where practical.

### ADAPT
The underlying idea remains valid, but language, audience framing or CTA needs to be rewritten for the new strategy.

### MERGE
Useful content exists in multiple old sections and should become one clearer page/section in the new IA.

### ARCHIVE
Historically meaningful content that should be preserved in research/history but is not appropriate for the public launch experience.

### RETIRE
Obsolete, duplicated, inaccurate, unsupported or strategically conflicting content that should not migrate.

## Strategic submission test
Every piece of existing content should answer these questions before migration:

1. Is it still factually current?
2. Is it first-party Rest Ezzz material?
3. Which audience does it serve?
4. Does it support the current primary mission?
5. Does it belong under Transition Support, Community Outreach, Acts of Compassion, Get Involved, About, or another approved area?
6. Is the original wording still appropriate?
7. Does it make a claim that needs independent verification?
8. Does it include personal information, testimonials or imagery requiring permission?
9. What should the next user action be?
10. KEEP / ADAPT / MERGE / ARCHIVE / RETIRE?

## New strategic destinations

### Transition Support
Use relevant existing copy about helping young people, guidance, resources, financial decisions, employment, housing, planning, mentorship, life skills or independence.

### Community Outreach
Use existing content about food distributions, outreach, community assistance, events, basic needs and local service.

### Acts of Compassion
Use existing stories/examples of direct practical kindness, resource-giving, food, clothing, blankets, services, community support and small actions that helped someone.

### Get Involved
Use volunteer, fundraising, partnership, service-provider and donor content.

### About
Use origin story, founder motivation, mission, values, organizational history and appropriate legacy context.

### Stories / Impact
Use substantiated stories, outcomes, events and community examples only when permission and factual support are adequate.

### Legacy / Historical
Funeral-expense and insurance-assistance material must be preserved during migration, but current status must be confirmed before it is placed into the new public IA.

## Migration inventory schema

For every captured section/content block record:

| Field | Purpose |
|---|---|
| Source URL | Exact live page |
| Old page/section | Original location |
| Original heading | Preserve source context |
| Original copy | Verbatim capture |
| Images/media | Original references |
| Existing CTA | Original action |
| Evidence state | First-party / corroborated / etc. |
| Current? | yes / no / unknown |
| Classification | KEEP / ADAPT / MERGE / ARCHIVE / RETIRE |
| New IA destination | New page/section |
| Rewrite needed | yes / no |
| Verification needed | yes / no |
| Permission needed | yes / no |
| Notes | migration/editorial reasoning |

## Do not
- Do not rebuild the old site 1:1 merely because it is live again.
- Do not delete historical content before capture.
- Do not publish old program claims as current without verification.
- Do not replace useful authentic Rest Ezzz language with generic nonprofit copy unnecessarily.
- Do not force all old content onto the homepage.
- Do not let the legacy site override the current founder interview and approved new strategic direction.

## Desired result
The new site should feel like the **same organization with a clearer, more complete identity**, not an unrelated replacement website.

The content migration should preserve Rest Ezzz's authentic history, language and community work while organizing it around:

1. Foster-youth transition support
2. Practical mentorship and resource navigation
3. Community outreach
4. Acts of Compassion
5. Referral partners
6. Community participation / volunteering / services
7. Donation and fundraising
